- `pnpm db:seed` (`scripts/seed.ts`, `scripts/seed-data.ts`): three past Saturdays (2026-10-17, 10-24, 10-31) from fixtures, 22 alliances, one rehearsal, run logs, app errors. `--reset` empties the app tables.
- Screenshots: `docs/screenshots/06-{main,alliance,admin}-{360,390,1280}.png`.

## Decisions
- Full numbers: one "Exact" checkbox in the header switches every number on the page, using CSS `:has()` and no JavaScript. Per-row `<details>` holds freshness times and name history.
- Admin gate: a right PIN on `POST /api/admin/session` (same limiter as the other PIN routes) sets a session cookie holding an HMAC of the PIN under `CRON_SECRET`. The admin pages render only the PIN sheet without it. The PIN is also kept in `sessionStorage` so the action buttons can send `x-edit-pin`.
- Members "(+3/−1)" on the main table needs one query of member uids for the event's two snapshots (about 4,000 rows, no aggregate).
- Member deltas appear only when both alliance rows are fresh and not failed; joined/left members show no delta.
- `snapshot_not_due` (409) is shown as "Not due until <before_at>". Failed lists that include `not fetched:` alliances are counted, not parsed.
- Admin read models import `lib/rehearsal`, so `lib/queries/admin.ts` is imported by path, not through `lib/queries/index.ts`.
