# 11c — Workspace sign-in and shell

Closes #295. Part 1 of #305 (the workspace dictionary) and part 1 of #312 (the README "Workspace setup"). Decisions D73 (the implementation choices D71 left open) and D75 (owner principle: the workspace is for people, never punitive).

## Built
- **Schema** (`lib/schema.ts`, migration `drizzle/0019_furry_fabian_cortez.sql`, generated by `pnpm db:generate` on top of `dev`'s `0017_first_victor_mancha` and `0018_nosy_loki`):
  - `workspaces`: id, slug (unique), union_id (unique), discord_guild_id, leader_role_ids text[], created_at;
  - `workspace_users`: id, workspace_id, discord_user_id, display_name, allowlisted, allowlist_added_by, allowlist_expires_at, blocked, last_login_at; unique (workspace_id, discord_user_id);
  - `workspace_sessions`: token_hash pk, workspace_id, workspace_user_id, created_at, expires_at; index on workspace_id.
  - Foreign keys cascade on delete. `truncateAll` (test helper) truncates the three tables.
- **`lib/private/`**:
  - `access.ts`: `requireWorkspace(db, slug, cookies, now)` returns a branded `WorkspaceAccess` (workspace id, union id, slug, user) or a refusal: `no_workspace`, `signed_out`, `other_workspace`, `expired` (the row is deleted), `blocked`. Also `signOut`.
  - `session.ts`: a 32-byte random token in `__Host-lap_ws` (HttpOnly, Secure, SameSite=Lax, 24 h); only its sha256 is stored. `revokeSession` deletes one session, only inside its own workspace.
  - `sign-in.ts`: `startSignIn` puts the state (`<slug>.<random>`) in `__Host-lap_ws_state` (10 min). `finishSignIn` does the rest:
    - a rate-limit check on `w:ip:<address>`;
    - the state compared with `secretEquals`; a mismatch is counted and gets 400 `bad_state`;
    - the code exchange and the member read;
    - access through a leadership role, or an allowlist entry that has not expired;
    - a `workspace_users` upsert and a session only on success.
  - `discord.ts`: the authorize URL (`prompt=consent`, or `prompt=none` when silent), the token exchange (HTTP Basic), `GET /users/@me`, `GET /users/@me/guilds/{id}/member` (404 = not in the server). Responses are parsed with zod. The base comes from `DISCORD_API_BASE_URL`.
  - `http.ts`: `NO_STORE`, the same-origin JSON check (Origin = app origin, Sec-Fetch-Site same-origin when sent, `application/json`), 303 redirects with cookies, a request cookie reader.
  - `log.ts`: `privateLog(code, numbers)`.
  - `dictionary.ts`: typed `en` / `pt-BR` / `fr`, the `lap_ws_lang` cookie, `pickWorkspaceLanguage`.
- **Routes** (`app/(private)/api/w/`):
  - `GET [slug]/login[?silent=1]`;
  - `GET auth/callback`, one fixed path for every workspace;
  - `POST [slug]/logout` with body `{}`, same-origin JSON only (403 otherwise).
  - Every answer carries `Cache-Control: private, no-store`, from the handler and from `proxy.ts`. Errors are codes.
- **Pages** (`app/(private)/w/[slug]/`):
  - The layout has static metadata ("Officers’ Desk", noindex) and reads nothing.
  - `page.tsx` runs the access check first. Then it shows one of three things:
    - the sign-in, with the reason for a failed attempt (`?e=denied|discord|not_configured`);
    - an expired session: a redirect to `login?silent=1`;
    - the shell: the burgundy header (workspace name, alliance tag · name, EN · PT · FR, "Signed in as … · Sign out"), Home with a placeholder that says the Members tab comes next, and five bottom tabs. Home is the only live tab; the other four are marked disabled with "Soon" in their accessible name.
  - `no-access/page.tsx` explains `not_member`, `no_role`, `allowlist_expired` and `blocked` in plain words. It reads nothing.
  - Tab marks come from the brand's proposed `tab-*.svg`. A `--burgundy` token (#6e2142 light, #7d2c4f dark) is in `lib/brand/tokens.css`.
- **`/admin` Workspaces card** (`app/_ui/admin/Workspaces.tsx`, `WorkspacesCard.tsx`, `lib/queries/workspaces.ts`, `lib/repo/workspaces.ts`, `lib/copy-admin-workspaces.ts`), with three PIN routes:
  - `POST /api/admin/workspaces`: add or edit; the union id must be in `ALLIANCES`; 409 `slug_taken`;
  - `.../allowlist`: a Discord user id until the end of a date, UTC;
  - `.../sign-out`: "Sign out everyone in this workspace".
- **Fence** (`eslint.config.mjs`):
  - the zones are now one list that each block extends;
  - an allowlist zone: every file outside `app/(private)` and `lib/private` is refused `lib/private`;
  - the `lib/repo` zone covers `app/(private)`;
  - `lib/private` is refused every `lib/notify*` and `lib/discord-*` module (listed from the folder at lint time).
  - `lib/private/roster-fields.test.ts` scans app, lib, config, scripts and `proxy.ts`. It allows only lib/repo, lib/private, `lib/collector*.ts`, `lib/raw-json.ts` and `lib/queries/blocked-keys.ts`.
  - `docs/ARCHITECTURE.md` lists both layers and the rule.
- **Env:** `DISCORD_CLIENT_ID` and `DISCORD_CLIENT_SECRET` are optional, and `DISCORD_API_BASE_URL` defaults to `https://discord.com/api`. The secret is in `secretsOf` (the redaction list). `.env.example` has the names only.
- **README** "Workspace setup": the Discord app steps, both callback URLs, the env names, the server and role ids (with OGs' ids as the example), `/admin` registration, `/w/ogs`, the home screen, troubleshooting.

## Decisions
- D73 records the callback path, the login/logout paths, `DISCORD_API_BASE_URL`, the cookie names, the `w:ip:` rate-limit key, who is stored, the /admin card and the no-access reasons.
- D75 records the owner's principle with the 2026-11-16 refinement: data that was not captured is never counted against anyone, and real signals are shown to the leadership with their evidence as "Check in" reasons.
- A bad state counts under its own `w:ip:` key, not the PIN's `ip:` key, so stray callbacks never lock the owner out of `/admin`.
- Only accounts that get in are stored; a refused account leaves no row.
- Allowlist access does not need membership in the Discord server (D71: "or when the Discord user id is on the allowlist").
- The roster-field test matches x, y and active only as string literals, and ignores comments. As `.x` or `active:` they are everyday SVG, date and Tailwind code, so a textual scan cannot tell them from a roster read. The five snake_case names are matched as a property, a key or a string.

## Deviations
- **Session length.** Issue #295 says 7 days; D71 (newer) says 24 h. Built 24 h.
- **"OGs seeded".** Issue #295 asks for it, but nothing is seeded: the owner registers OGs on the /admin card (D73), because server and role ids are data, not code. The e2e registered it that way.
- **Sign-in lead.** The sign-in page does not name the alliance: the refusal carries no workspace data before sign-in.
- **Page Cache-Control.** `proxy.ts` sets `private, no-store` on `/w/...`, but Next replaces a page's `Cache-Control` with its own for a dynamic render. In `next dev` that is `no-store`. Route handlers keep `private, no-store`. A production build was not run here.

## Open issues
1. **Root layout read on /w pages.** The root layout's `UpstreamBanner` reads the public upstream status from the database on every page, `/w/...` included, before the page's access check. It reads nothing private. Moving `/w` out of the root layout needs separate root layouts: not done.
2. **The root `opengraph-image`.** The public site card may still apply to `/w/...`. It is the public card, with no workspace data.
3. **`blocked` has no writer.** It is checked at sign-in and on every request, but neither /admin nor the workspace can set it yet.
4. **No allowlist removal.** The /admin card can add an entry or move its date, not remove one (set a past date instead).
5. **One session cookie per browser.** Signing in to a second workspace replaces the first one's session cookie.
6. **`prompt=none` against the real Discord is unverified.** Only the stub was used. If the real Discord shows its consent screen for `prompt=none`, the officer taps Authorize once a day.
7. **Migration number.** The orchestrator renumbers `0019_furry_fabian_cortez` if another migration merges into `dev` first.
