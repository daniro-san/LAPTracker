## D85 — Server power balance: a public page of alliance-level shares, a hypothetical bloc builder and the top 3's share over time (2026-11-16, owner, 08zzzzm, issue #283)

Why: pacts and kingship arithmetic. On 2026-11-16 server might is 58.5 B, no alliance holds more than 8.7 % and the top 3 hold 23.8 % (21.5 % on 2026-11-05): kingship needs a coalition, and the top is slowly concentrating.

- **Public, alliance-level only.** `/alliances/balance` (linked from the title row of the home and event pages as "% Server balance"). It reads alliance totals from `daily_rosters` (`total_power`, `member_count`, tag, name, badge id); no member row, name or roster key is selected (`lib/queries/balance.ts`). Wording is neutral: shares and arithmetic, no ranking of who is weak, no verdict.
- **Which readings count: daily reads only (D60), event rosters do not.** A daily read takes every alliance on the same server day, so shares compare like with like; event Start and End rosters are read at different minutes per alliance and, on a scheduled event's day, the daily read is skipped (D60), so that day is a gap in the trend. Each alliance's might is its newest usable daily roster (`dailyFit`: fresh, no error, not empty) in the last 90 days (`BALANCE_DAYS`). An alliance whose newest read is older than the newest day shows "as of <date>" on its row.
- **Which alliances.** Every alliance with a usable daily roster in that window (the tracked alliances, D4). The kingdom's total is the sum of those alliances' might, shown beside the stacked bar as "Server might". It is the tracked alliances' total, not the whole server's.
- **First screen.** One sentence: "No alliance holds more than {max} of the server's might; the top 3 hold {top}." `max` is rounded up to a whole percent so the sentence stays true; `top` is rounded to the nearest. A line under it: "Might includes buildings and tech."
- **The stacked bar** is HTML boxes (D68): every alliance, greatest first, alternating two inks, with a bloc's alliances in plum (A) and yarn (B). Each alliance's share is in the list under it (one decimal), so no label is needed in the 6 to 30 px segments at 360 px. The list is the legend and the bloc taps.
- **The bloc builder.** State is the URL: `?a=<union ids>&b=<union ids>`. Each row has two GET links, A and B (44 × 44 px), that add the alliance to that bloc or remove it (a tap on the other letter moves it); each link returns to its own row (`#alliance-<id>`) and a sticky line under the header keeps both blocs' shares in view while the list scrolls. A bloc card shows its share of the server's might, total might, members and alliance count. An alliance is in at most one bloc (named in both: A keeps it; `lib/balance.ts`). Unknown or repeated ids are dropped.
- **No default blocs.** The builder is empty by default. Each card is labelled "Hypothetical", the help line says it is arithmetic, not a forecast and not an announcement, and a URL with blocs carries `robots: noindex`.
- **Concentration over time.** The top 3's share of the tracked alliances' might per daily read, as the first chart's line (`LineChart`, D68), over the days on which every alliance of the current list has a usable roster (a day with fewer would compare a smaller server). A sentence gives the first and last values, and a Details table every day with the server might.
- **Pure arithmetic** in `lib/balance.ts` (shares sum to 1, a bloc's share is the sum of its members' shares, at most one bloc per alliance, a URL round trip), property-tested; the read has a PGlite test.
- **Not done.** Saved or named blocs, a "share needed for kingship" threshold, a per-alliance trend, event rosters in the figures, member-level figures, an Open Graph picture for the page.
