## D77 — PostHog on production: page views, typed events, client errors and session replay on every page, masked per area (2026-11-16, owner, issue #326)

The owner asked to "map some events, record sessions, capture errors" with PostHog. This extends D36 (Vercel Web Analytics and Speed Insights stay as they are) under a new decision. Owner choices made on 2026-11-16, during the session: PostHog's **US** cloud; PostHog on **every** page, `/admin` included, with session replay everywhere and masking per area; the key is the Vercel variable `POSTHOG_KEY`. The data PostHog receives is anonymous: no cookie or storage, no identify, no visitor IP, no query string or hash, every input masked, and the text of the workspace and `/admin` masked in replay.

- **What.** `posthog-js` 1.444.4, its `no-external` build: it never loads a script from PostHog. Exception capture is imported with it, and the replay recorder (`posthog-js/dist/posthog-recorder`) is a separate chunk of our own build, fetched only when a page is recorded. The SDK chunk itself is requested after the window `load` event, in an idle moment (`requestIdleCallback`, or a `setTimeout` where it does not exist), so it never delays the page; events tracked before it arrives wait for it, and a failed load leaves tracking a no-op. `app/layout.tsx` reads `POSTHOG_KEY` on the server and renders `app/_ui/PostHogAnalytics.tsx` with it as a prop only when `VERCEL_ENV === "production"` and the key is set. So previews (which have a Preview value of the key), `next dev`, `next start` and tests load nothing and send nothing. The project key is public by design: it is in every production page's HTML. The SDK's settings are in `lib/analytics/posthog.ts`. They do not rely on the project's defaults: the local check served a project config with console and network capture on and input masking off, and the SDK's own settings won.
- **Where it goes.** The region is one constant, `lib/analytics/region.ts`. The browser sends everything to `/ingest/...` on our own origin. `app/ingest/[...path]/route.ts` (`lib/analytics/ingest.ts`) forwards only the paths the SDK uses: `POST /e/`, `/i/v0/e/` (the events endpoint PostHog's remote config can name) and `/s/` to `us.i.posthog.com`, and `GET /array/<key>/config` (the remote config) to `us-assets.i.posthog.com`. Any other path answers 404, and a body over 1 MB answers 413, without a request to PostHog. The remote config keeps PostHog's `cache-control`, or `public, s-maxage=300` when it has none; ingestion answers `no-store`. It forwards only the body, its `content-type` and `content-encoding`, PostHog's own query string (`ver`, `compression`, a timestamp) and our origin, which PostHog uses for the project's authorized domains. The visitor's cookies, `x-forwarded-for`, referer and user agent header are not forwarded, so PostHog sees Vercel's address, never the visitor's. A next.config rewrite was not used: Next proxies a rewrite with every request header (`next/dist/server/lib/router-utils/proxy-request.js`, httpxy), which would send the workspace and `/admin` session cookies and the visitor's IP to PostHog. PostHog's paths end in a slash (`/e/`, `/s/`). `next.config.ts` sets `skipTrailingSlashRedirect`, and `proxy.ts` keeps the 308 to the path without the slash for every path except `/ingest/`.
- **What leaves the browser.**
  - Page views and page leaves; click autocapture on public pages only, on purpose: it feeds PostHog's click heatmaps, and the clicked text there is public game data. On a public page that is the element chain, the clicked link's or button's text and its `href`. Input values are never captured. Click autocapture is off on `/w` and `/admin`.
  - Exceptions: type, message and stack frames. On the workspace and `/admin`, which show per-member values (D71, D76), the message is replaced by `[masked]`; the type and frames stay. A pattern rule (a coordinate pair, a timestamp) would miss a value printed any other way and does not catch names, so the whole message goes. Public pages never receive the blocked roster fields (D76, `lib/queries/blocked-keys.ts`).
  - Six custom events (`lib/analytics/events.ts`), a closed list whose properties are only closed lists of words: `ws_sign_in_completed`, `ws_first_use_done`, `ws_first_use_skipped`, `ws_copy_spreadsheet`, `ws_filter_used` (`all`, `new`, `checkin`, `missing`, `r4`: the Members tab's filters) and `ws_language_switched` (`en`, `pt-BR`, `fr`). A type test fails `pnpm check` if a property could take any string. Where each is sent:
    - the sign-in, from a `#signed-in` fragment that the sign-in callback adds only when analytics is on (production with `POSTHOG_KEY`);
    - first use done (Start on the last card) or skipped (Skip or Escape), on the first visit only: walking the cards again from "?" → Replay is not counted;
    - the Members tab's "Copy for spreadsheet";
    - a filter chip's click, before the link loads the filtered list: the filter's name only, never the address with `?f=` or the search `?q=`;
    - the EN · PT · FR switch, when the language changes.
    - Added in 11k (issue 299, D96): `ws_screenshot_sent`, once per picture the desk's "Send screenshots" read, and `ws_draft_saved`, once per saved draft, each with only `kind`: one of the import's types (`ScreenshotKind`), `unrecognised` or `map`. The Discord command sends no event.
  - With every event: `area` (`public`, `workspace` or `admin`) and, on `/w/<slug>`, `workspace` (the slug), set in `before_send` from the event's own path, so an event sent during a client-side navigation never carries the previous page's area. PostHog's standard properties: browser, OS, device type, screen and viewport size, browser language, time zone, the raw user agent, the page title, and random ids that live only for one page load.
  - `before_send` (`lib/analytics/sanitise.ts`, tested) cuts the query string and hash from every URL-like property: `$current_url`, `$pathname`, `$referrer`, `$session_entry_url`, `$prev_pageview_*`, `$external_click_url`, `href`s in the element chain, stack frame file names and URLs inside exception messages. It also drops what posthog-js reads from a query string even with `save_campaign_params: false`: `$session_entry_utm_*`, the click ids (`gclid`, `fbclid` and the rest of its list) and `ph_keyword`.
  - Nothing identifies a person. There is no `identify` and no person profile (`person_profiles: "never"`), and no Discord id or name is sent. There is no cookie and no storage (`persistence: "memory"`): a visitor gets a new random id on every full page load, so "unique visitors" in PostHog counts page loads, not people. The device model and campaign parameters are not read.
- **Session replay.** `followPath` (`lib/analytics/posthog.ts`) starts and stops it on every navigation.
  - **Public pages:** a session is recorded in 25 % of page loads (`PUBLIC_REPLAY_SAMPLE`), so public visitors cannot use up the free recordings before the workspace. Text stays readable: it is public game data.
  - **`/w/**` and `/admin/**`:** always recorded. Their layouts wrap the page in the class `ph-mask`. Under it, every text is replaced by stars and every attribute but styling and sizes is emptied (`aria-label`, `title`, `alt`, `href`, `datetime`…). Images and form fields are blocked: they replay as empty boxes of the right size. The `/admin` PIN field is blocked, so neither its value nor its length is recorded. The mask follows the DOM, not the URL, so it holds across client-side navigations between public pages and `/w`.
  - **Everywhere:** every input value is recorded as the same `***`, so the search box's typed name and its length stay in the browser. No console logs, no network requests, headers or bodies, no canvas. Replay URLs lose their query string and hash.
- **No consent banner** (owner, 2026-11-16). Nothing is stored on the device or read from it: no cookie and no local or session storage, checked in the browser. Nobody is identified. Our proxy never sends the visitor's IP, and the project discards IPs. Every input is masked. Readable replay text is limited to public game data. An open option, not built: a short privacy note in the footer that says this.
- **CSP unchanged.** The SDK and the recorder are chunks of our own build, loaded by Next's nonced runtime (`'strict-dynamic'`). The requests go to `/ingest` on our own origin (`connect-src 'self'`). `proxy.ts` gives `/ingest/*` answers the same deny-all CSP as `/api/*`. The local check found no `securitypolicyviolation`.
- **Free plan limits** (PostHog pricing page, 2026-11-16, organization-wide, reset monthly): 1M events, 5,000 recordings, 100,000 exceptions. Without a card nothing is charged: past a limit PostHog drops what arrives until the month ends, and the site is not affected. The proxy is a Vercel function: every PostHog request is one invocation (Hobby: 1M a month). A recorded page sends a snapshot batch every few seconds while something changes on it.
- **How this was checked.** Checks (a)–(f) were run manually with a Playwright harness against a local production build; the evidence is outside the repo, and `pnpm check` covers only the sanitiser, the type test and the fence test, plus the `/ingest` allowlist and cap and the sign-in fragment. The checks: (a) a public page sends page views with no query or hash, and, when sampled in, replay with readable text and the search input masked; (b) `/admin` sends events and replay with no text, PIN or member value; (c) `/w` replay has no unmasked text, and the officer's name and a member's name and coordinates are absent; (d) no CSP violation; (e) no PostHog cookie or storage; (f) the masking holds across client-side navigation between a public page and `/w`.
- **Owner's dashboard steps.**

  - After the merge: production gets the code at the next release (D29). Previews stay off even with their key.
  - Optional: Session replay → **Minimum duration** 5 seconds. The SDK applies it from the project config to every area; it has no local setting for it. The local check used 5 s.
