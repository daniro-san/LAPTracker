## D103 — Roll call: one occasion at a time, a ✓ / ✗ pair per member, "the rest" per kind, away dates with a first day, and Elixir Scramble teams of 20 (2026-11-17, 11w, issue 298)

Why: officers mark the KvK shield, the Undead Siege, plunders and the Elixir Scramble every week in spreadsheets (#293: "Shield … 0 % filled"). The owner's rules for #298: the default is unmarked, never "did"; "the rest" depends on the activity; away members are skipped; rows never move while being tapped; Elixir Scramble is per team, up to 20 players, built before registration closes. D75 applies throughout: marking is for planning and thanks, never for punishment.

- **Occasions.** A roll call is one occasion (`roll_calls`, migration `0028_roll_call`):
  - **From the Calendar:** a KvK entry's week is a "KvK shield" roll call, an Undead Siege's week an "Undead Siege" one (the issue's "raid"), an Elixir Scramble team's week that team's roll call. Keyed by (entry, the plan's Monday). Its row is written with the first mark or pick, so reading a page writes nothing. Deleting the Calendar entry keeps the roll call and its marks (`entry_id` set null).
  - **Added by hand:** KvK shield, Undead Siege or plunders on a day ("Add a roll call"). The sheet sends a request id (D100), and a second add of the same kind and day opens the first one.
  - An Elixir Scramble roll call starts only from its Calendar entry, which holds the team and the window (09:00, 18:00 or 23:00 ST).
- **Marks.** `roll_call_marks`, append-only like member facts (D80): each write of one member's mark is the next version, unique per (roll call, member, version). The values are `yes`, `no`, `assumed` ("no problem seen") or null (cleared).
  - A tap names the version the officer saw. Another officer's newer mark refuses it (409) with that mark, who set it and when ("Ana marked “Did not join” just now."), and the row shows theirs; tapping again then changes it. The same mark sent twice is not a conflict.
  - Each kind has its own words: Shield up / No shield, Joined / Did not join (Elixir Scramble), Took part / Not this time (Undead Siege, plunders).
  - The same button tapped again clears the mark.
- **"The rest"** fills only members with no mark, never one somebody marked meanwhile, and never an away member. Then "{n} marked “…”. Undo"; the undo clears only the marks it wrote that nobody changed since.
  - KvK shield: "No problem seen for the rest", stored as `assumed` (owner: never turn "unknown" into "did" silently). It is counted apart from "Shield up".
  - Elixir Scramble: "The rest did not join" (owner: the joiners are the few).
  - Undead Siege and plunders: "The rest took part". The owner named only the two above; these two follow the prototype's "All the rest did it" and lean to the member's favour (D75).
- **Not set never counts (D75).** Counts read "Shield up 12 · No shield 2 · No problem seen 70 · Not set 10 · Away 3". Not set is never added to the ✗ side, and no screen sorts or flags anyone by it. Nothing reads the marks to make a status or a reason; a "Follow-up" use is for its own issue.
- **Order.** The page opens with not set first, then marked, each by name, away members last. The order is fixed while the page is open: a tap never moves a row.
- **Away dates** (D80 amended). The `away` fact gains an optional `from`, the first day away: `{ text, from?, until }`. A note runs on day d when `from` (if any) ≤ d ≤ `until`. A note without `from` runs from when it was written, as before. While it runs, or while an officer's "On a break" status is set, the member is left out of the roll call (listed apart as "Away, left out" with the last day), of "the rest", of the counts' answers, and of caravan and Elixir Scramble suggestions (`awayOn` in `lib/private/fact-fields.ts`, also used by `caravans.ts`). The Members statuses follow the same rule, so a note with a later first day shows On a break only from that day. "Someone is away" on the roll call and the facts editor both write it; a stale write gets the newer note with Keep theirs / Use mine.
- **Elixir Scramble teams** (`roll_call_team`). Up to 20 players per team (the game's own limit), a member on one team per week. A pick names the member and stores their name; one team's changes run one at a time (row lock).
  - The picker lists the team first, then everyone not away that day in the suggested order: daytime for them at the window (08:00–22:59 on their own clock, D98), then no time zone recorded, then night; within each, active this week, then main squad might. A member with no time zone is never put after one asleep (D75).
  - The page gets the order and "Active this week", never the activity number (D76, as the caravan suggestions).
  - "Add the first n suggested" fills the free places in that order.
  - The team's roll call asks only its members.
- **Screenshots (D96's coming-soon kinds) stay coming soon.** Elixir teams: the owner said the roster is visible only on Friday and teams are marked in the app (2026-11-16). Undead Siege result: the mail holds only the alliance's total waves and level, nothing per member to mark. Damage event (Cheese Trap): Cheese Trap is not one of #298's occasions, and its result (phase, total damage, MVP, per-member damage) is not a roll call mark.
- **Not built.** The registration deadline (Wednesday or Thursday, unconfirmed by the owner); the Elixir availability poll (owner: not kept); filling a roll call from a photo.
- **Privacy.** The route runs its work in `privately` (D80), so an error leaves as a code. Nothing is logged. The pages run `requireWorkspace` first. Only the workspace's own alliance's members can be marked or picked (D71).
