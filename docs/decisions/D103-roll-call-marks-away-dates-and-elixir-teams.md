## D103 — Roll call: one occasion at a time, a ✓ / ✗ pair per member, "the rest" per kind, away dates with a first day, and Elixir Scramble teams of 20 (2026-11-17, 11w, issue 298)

Why: officers mark the KvK shield, the Undead Siege, plunders and the Elixir Scramble every week in spreadsheets (amended 2026-11-17: plunders are no longer added; see the amendment below) (#293: "Shield … 0 % filled"). The owner's rules for #298: the default is unmarked, never "did"; "the rest" depends on the activity; away members are skipped; rows never move while being tapped; Elixir Scramble is per team, up to 20 players, built before registration closes. D75 applies throughout: marking is for planning and thanks, never for punishment.

- **Occasions.** A roll call is one occasion (`roll_calls`, migration `0029_roll_call`):
  - **From the Calendar:** a KvK entry's week is a "KvK shield" roll call, an Undead Siege's week an "Undead Siege" one (the issue's "raid"), an Elixir Scramble team's week that team's roll call (amended 2026-11-17: a Cheese Trap entry's week is a Cheese Trap one). Keyed by (entry, the plan's Monday). Its row is written with the first mark or pick, so reading a page writes nothing.
  - **The Calendar changes after a roll call started.** Deleting the entry keeps the roll call and its marks (`entry_id` set null). A week skipped or moved out of the week, or an entry deleted, leaves the roll call on the week list with the added ones, on its own day, with its marks.
  - **Added by hand:** KvK shield, Undead Siege or plunders on a day ("Add a roll call") (amended 2026-11-17: plunders are no longer added; see the amendment below; the sheet offers KvK shield, Undead Siege and Cheese Trap). The sheet sends a request id (D100). A unique index on (workspace, kind, day) over the hand-added rows (those with a request id) keeps one per kind and day; a second add, or one that loses a race, opens the first. The index leaves out Calendar roll calls, so a Calendar delete that sets `entry_id` to null can never collide with it.
  - **Plunders** are when the alliance plunders caravans or Black Ops (owner, 2026-11-17). The add sheet says so under the choice. The label stays "Plunders" / "Saques" / "Pillages". (Amended 2026-11-17: the plunder choice and this line are off the sheet; the label stays for the plunder roll calls already saved.)
  - An Elixir Scramble roll call starts only from its Calendar entry, which holds the team and the window (09:00, 18:00 or 23:00 ST).
- **Marks.** `roll_call_marks`, append-only like member facts (D80): each write of one member's mark is the next version, unique per (roll call, member, version). The values are `yes`, `no`, `assumed` ("no problem seen") or null (cleared).
  - A tap names the version the officer saw. Another officer's newer mark refuses it (409) with that mark, who set it and when ("Ana marked “Did not join” just now."), and the row shows theirs; tapping again then changes it. The same mark sent twice is not a conflict.
  - Each kind has its own words: Shield up / No shield, Joined / Did not join (Elixir Scramble), Took part / Not this time (Undead Siege, plunders; amended 2026-11-17: also Cheese Trap).
  - The same button tapped again clears the mark.
- **"The rest"** fills only members with no mark, never one somebody marked meanwhile, and never an away member. The button names the count and the default ("Mark the other 57 as took part"); beside it "57 not set · 3 away, left out"; with nothing left the bar says only "All marked". After the tap the bar reads "57 marked as took part · Undo" for about 10 seconds, and "Undo the rest" stays by the counts while any of those marks is unchanged. The undo clears only the marks it wrote that nobody changed since.
  - KvK shield: "no problem seen", stored as `assumed` (owner: never turn "unknown" into "did" silently). It is counted apart from "Shield up".
  - Elixir Scramble: "did not join" (owner: the joiners are the few).
  - Undead Siege: "took part" (owner, 2026-11-17).
  - Plunders: none (owner, 2026-11-17); each plunder is marked one by one. Amended 2026-11-17: still none for the plunder roll calls already saved.
  - Cheese Trap (amended 2026-11-17): "took part", as the Undead Siege. This is an assumption the owner can change.
- **Not set never counts (D75).** Counts read "2 of 58 marked · Shield up 1 · No shield 1 · No problem seen 0 … · Not set 56 · Away 3", "no problem seen" and away only when above zero. Not set is never added to the ✗ side, and no screen sorts or flags anyone by it. Nothing reads the marks to make a status or a reason; a "Follow-up" use is for its own issue.
- **Order.** The page opens with not set first, then marked, each by name, away members last. The order is fixed while the page is open: a tap never moves a row.
- **Away dates** (D80 amended). The `away` fact carries `from`, the first day away: `{ text, from?, until }`. A note runs on day d when `from` ≤ d ≤ `until`.
  - **Nothing reaches into the past.** A note saved without a first day gets the server day of the save as `from` (the facts route sets it; the away sheet opens a new note on today). A note saved before this rule, without `from`, runs from the server day its version was written. An officer's "On a break" counts from the server day that status was set. So a past roll call, and a past week's caravan suggestions, read the same after a later note.
  - While a note runs, or a break counts, the member is left out of the roll call (listed apart as "Away, left out" with the last day), of "the rest", of the counts' answers, and of caravan and Elixir Scramble suggestions (`awayOn` in `lib/private/fact-fields.ts`, also used by `caravans.ts`). The Members statuses follow the same rule, so a note with a later first day shows On a break only from that day.
  - "Someone is away" on the roll call and the facts editor both write it, the first day not after the last; a stale write gets the newer note with Keep theirs / Use mine. The card reads "Nov 20 – Nov 25" with a first day, "until Nov 25" without.
- **Elixir Scramble teams** (`roll_call_team`). Up to 20 players per team (the game's own limit), a member on one team per week. A pick names the member and stores their name.
  - Changes to a week's teams run one at a time under one lock per workspace and week (`pg_advisory_xact_lock` on a hash of both), taken before the other team is read, so two officers adding one member to Team A and Team B at once cannot both win. A roll call whose Calendar entry was deleted is not a team any more and is left out of that check.
  - The picker shows the team first, then everyone not away that day under "Daytime for them" (08:00–22:59 on their own clock at the window, D98), "No time zone recorded" and "Night for them", best picks first (active this week, then main squad might), then "On the other team" (not pickable). A member with no time zone is never put after one asleep (D75).
  - The page gets the order and "Active", never the activity number (D76, as the caravan suggestions).
  - The counter and "Add the first n suggested" stay at the top; at 20 the Pick buttons are off and it says "Team is full".
  - **Registration** (owner, 2026-11-17): open until Wednesday (ST) of the Scramble's game week, closed from Thursday 00:00 ST. The Elixir card and the picker say "Registration closes Wednesday (ST)" or "Registration closed". Team edits stay allowed after it closes, so officers can fix the team.
  - The team's roll call asks only its members.
- **Screenshots (D96's coming-soon kinds) stay coming soon.** Elixir teams: the owner said the roster is visible only on Friday and teams are marked in the app (2026-11-16). Undead Siege result: the mail holds only the alliance's total waves and level, nothing per member to mark. Damage event (Cheese Trap): Cheese Trap is not one of #298's occasions, and its result (phase, total damage, MVP, per-member damage) is not a roll call mark. (Amended 2026-11-17: Cheese Trap now has a roll call of who took part; its damage screenshot stays coming soon.)
- **Not built.** The Elixir availability poll (owner: not kept); filling a roll call from a photo.
- **Privacy.** The route runs its work in `privately` (D80), so an error leaves as a code. Nothing is logged. The pages run `requireWorkspace` first. Only the workspace's own alliance's members can be marked or picked (D71).
