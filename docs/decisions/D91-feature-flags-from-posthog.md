## D91 — Four features are switched by PostHog feature flags, read on the server, off unless PostHog says on (2026-11-17, owner, 08zzzzs)

Why: the owner wants to turn the merge simulator, the charts' Details tables, kill share vs might share and the war turnout on or off himself, whenever he wants, without a deploy. PostHog is already the project's analytics (D77), and its feature flags do this on the free plan.

- **Rule.** `lib/flags.ts` (server only) reads the flags from PostHog's public `/flags` endpoint. A feature shows only when its flag exists in PostHog and is on. The page or the server component that draws the feature reads the flag at render time; client components and components with tests get a boolean. No flag SDK reaches the browser, so nothing flashes and the browser sends nothing for flags. Where a page or function is at the lint size limit (300 lines per file, 80 per function), the async server component that draws the gated part reads its own flag (`AllianceLinks`, `AllianceStanding`, `PlayerProgress`, `LiveSections`, `BalanceTrend`).
- **The four flags (exact keys) and what each hides when off.**
  - `merge-simulator`: `/alliances/merge` answers 404 (the page and its metadata call `notFound()`), and every link to it is left out: "Simulate a merge" on the event's alliance page (`app/_ui/AllianceLinks.tsx`) and "Merge simulator →" under the member flow (`app/_ui/FlowView.tsx`). No sitemap exists; `robots.ts` lists only `/admin`.
  - `chart-details`: the Details disclosure under each chart: the player page's daily progress (`PlayerProgress`, the readings table), the event page's server pulse (`LivePulse` `Pulse`, the interval table), the fight clock rows and the compare page's server pulse (`PulseDetails` from `PulseStrip.tsx`), the alliance page's standing over time (`Standing.tsx` `RanksTable`) and the balance page's top-3 trend (`BalanceRows.tsx`, the trend table). Every chart keeps its summary line. The Details of tables that are not charts stay: `StatTable`, `EventCompare`, `PlayerAcrossEvents`, the event-alliance page's rank card.
  - `kill-vs-might`: the event page's "Kill share vs might share" section (`WhoCarried`) is not rendered and `whoCarried` is not run.
  - `war-turnout`: the event page's "War turnout" / "War turnout so far" section (`WhoFought`) is not rendered and neither `memberTurnout` nor `memberTurnoutSoFar` (the D79 `turnout-so-far` entry) is read; kill share vs might share then has no "{share} with kills" figure in its rows, because that figure comes from the same read; the merge simulator has no "War turnout" section and does not read it; the End's public Discord message has no "Most members with kills gained" line and its picture no turnout block (`lib/run-notify.ts` does not read the turnout).
- **Fail closed.** A flag is on only when the answer has `flags[key].enabled === true`. A missing key, `enabled: false`, a non-2xx status, a network error, a timeout (1.5 s) or a body that is not JSON is off. `errorsWhileComputingFlags` is not read: a flag PostHog could not compute is missing or not enabled, so it is off.
- **Cache.** One read per minute per server instance: Next's data cache (`unstable_cache`, key `flags`, tag `flags`, `revalidate: 60`), as `lib/event-cache.ts` (D79) does, and React `cache()` within one request. A change in PostHog shows within about a minute (plus one request: an expired entry is served once while Next reads it again). A failed read is not stored: the cached function throws, so a failed refresh keeps the last answer (Next's `unstable_cache` behaviour, not tested here). A failed first read is off, and that failure is remembered on the server instance for 30 s, so an outage costs one 1.5 s timeout per 30 s per instance, not one per page; concurrent reads on one instance share one request (both tested in `lib/flags.test.ts`). Pages start the flag read together with their database reads; only the gated reads wait for it. The Discord run reads the flag with the context's `fetch`. A flag value is never stored in the D79 event cache: the page reads the flag per request and skips the gated read when it is off.
- **Request.** `POST https://us.i.posthog.com/flags?v=2` (the host from `lib/analytics/region.ts`, D77), JSON body `{ "api_key": POSTHOG_KEY, "distinct_id": "laptracker-server" }`. The key is not an argument of the cached function, so it is not in the cache key or in the line Next logs when a refresh fails.
- **Privacy.** The request carries only the project key and the fixed distinct id `laptracker-server`: no visitor id, cookie, IP, path or header of the visitor. Every visitor sees the same value of a flag.
- **Where the key comes from.** `POSTHOG_KEY` (D77). Flags are read wherever the key is set, `VERCEL_ENV` not checked: production and previews read the same flags. Analytics stays production-only (D77).
- **Local override.** Without `POSTHOG_KEY` (local `next dev`, tests, CI) every flag is off, except the keys in `LOCAL_FLAGS` (comma-separated, e.g. `LOCAL_FLAGS=merge-simulator,chart-details,kill-vs-might,war-turnout`). `LOCAL_FLAGS` is read only when `POSTHOG_KEY` is not set, so it cannot turn on a feature on a deployment that has the key. Never set it on Vercel.
- **Owner's steps.** In PostHog, project 741657 → Feature flags → New feature flag, four times, with the keys `merge-simulator`, `chart-details`, `kill-vs-might` and `war-turnout` exactly; type boolean; release condition: all users, 100 %. Turn a flag's "Enabled" switch on to show the feature and off to hide it; the site follows within about a minute. Until a flag exists and is on, its feature is off; after the merge and the next release (D29), all four features are hidden until their flags are created and on.
- **No new dependency.** `fetch` and Next's own cache; PostHog's server SDK is not needed for one request.
- **Tests.** `lib/flags.test.ts`: `enabled: true` is on; `enabled: false`, a missing key, a 500, a failed request and a body that is not JSON are off; the request body holds only the key and the fixed id; `LOCAL_FLAGS` counts only without a key. `lib/run-notify-turnout.test.ts`: with the flag off the End's message reads and sends no turnout.
