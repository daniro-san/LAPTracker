## D102 — Notices: a copy per place, Publish to Discord by audience, earlier versions, a calendar link; no images yet (2026-11-17, 11v, issue 345)

Amends D71 ("lib/private sends no Discord message") for one case, "Publish to Discord", and D81's read page (one Copy per language becomes three). Builds on D100 (request ids) and issue 293 (field versions).

Why: the leadership pastes each notice in three places, the game's notice board, the game's mail and Discord, each with its own rules, and asked to post to Discord from the notice (issue 345, owner comments of 2026-11-16 and 2026-11-17). The edit history was stored (`notice_edits`) but no screen showed it.

**Copy formats** (`lib/private/notice-formats.ts`, pure). Each language on the read page has three buttons:

- **Copy for game notice**: the text alone (the board has its own title field), `\n` line breaks, no spaces at line ends, no blank lines at either end. Over 1,000 characters (`NOTICE_LIMIT`: the owner's figure for the game's notice board, issue 304; counted as graphemes, so an emoji is never cut in two) it is cut after the last whole line that fits (a line that ends exactly at 1,000 is kept), or the last word when one line is longer; the button then says "Copied the first 1000 characters" instead of "Copied".
- **Copy for game mail**: the same plain text, never cut. The mail's own limit is unknown.
- **Copy for Discord**: the title in bold, a blank line, then the text shown literally: `\ * _ ~ ` |`are backslash-escaped outside web addresses,`#`, `>`and`-#`at a line's start are escaped, and`@everyone`, `@here`and`<@` get a zero-width space, so a paste never pings anyone.

**Publish to Discord** (`lib/private/notice-publish.ts`, `POST /api/w/[slug]/notices/publish`).

- **Where.** The notice's audience picks the channel: "Show to members" on → the workspace's `members` channel; off → its `leaders` channel. For the OGs (owner, 2026-11-17) that is `#guides-and-beyond` and `#notices` (R4/R5 only). The channels are configuration, never guessed from a name and never in code.
- **Configuration.** One Vercel variable, `WORKSPACE_DISCORD_WEBHOOKS`, JSON by workspace slug: `{"ogs":{"members":{"url":"https://discord.com/api/webhooks/…","name":"guides-and-beyond","forum":true},"leaders":{"url":"…","name":"notices","forum":true}}}`. `lib/env.ts` validates it with zod (a Discord webhook URL, a name of 1–100 characters, `forum` true or false, default false); an error names the path, never the value. `forum` exists because Discord needs `thread_name` on a post to a forum channel's webhook and refuses it on a plain channel's. The URLs are on the log redaction list (`secretsOf`). They are never stored in the database or the repo. Without the variable, or without the audience's channel, the button is off and says "No Discord channel is set up for … notices yet. Ask the site owner."
- **Confirm.** The button opens a sheet titled "Post to #channel?" with each written language ticked; Post sends the ticked ones, in the page's order.
- **What is posted.** Each message has `allowed_mentions: {"parse": []}`. With several languages, each is under its name in bold ("**English**"). Languages share a message while they fit in 2,000 characters; a longer one is split at line breaks, and a line over 2,000 between whole graphemes. A forum channel (`forum: true`) gets a new post whose title is the notice's title (100 characters at most) with the first message, and the other messages go into that post (`thread_id`). A plain channel gets the title in bold at the top. Messages are sent one after another, each with a 5 s timeout, within a 40 s budget for the whole publish; when the budget is spent the rest is not sent and the publish is `failed`. The route declares `maxDuration = 60`. No image (see below).
- **Once.** The sheet makes one `crypto.randomUUID()` when it opens (D100). The route first claims a `notice_publishes` row under (workspace, request id) with `insert … on conflict do nothing`; a repeat or a second tap at the same moment gets the first claim's outcome and posts nothing: 200 when it was posted, 409 `posting` while it runs, 502 `failed`. A claim still `posting` after 2 minutes was left by a run that died, so it counts as `failed` and a retry is never held on 409. After a `failed` answer the sheet takes a new id, so the next Post tries again.
- **Cooldown.** A publish of the same notice to the same audience within 30 s of one that is running or was posted is refused with 409 `recent` ("This notice was posted to this channel less than a minute ago. Check the channel before you post again."), so two officers, or two sheets, do not post it twice. The check reads the notice's newest rows (`notice_publishes_notice_idx`).
- **Record.** `notice_publishes` (migration 0028) keeps who, when, the audience, the languages, the outcome (`posting`, `posted`, `failed`) and how many messages Discord took. No URL, channel name or text. The page shows the newest one that was posted: "Posted to #guides-and-beyond by Rook · Tue, Nov 17 14:02 server time · EN, PT".
- **Failure.** When Discord refuses a message or does not answer, the publish is `failed`, nothing is retried, and the sheet says "Discord did not take the whole notice. Check the channel before you post again." Messages already taken stay in Discord.
- **Logs.** `privateLog` only: `notices.publish.ok` (messages, languages, ms) and `notices.publish.failed` (Discord's HTTP status or 0, messages sent, messages planned, ms). Errors leave through `privately` as a code.
- **D71 amended.** lib/private still imports nothing from `lib/notify*` or `lib/discord-*` (the eslint fence stays). The publish posts with `AppContext.fetch`, as the "Send to LAPTracker" reply already does (D96). It sends only what an officer wrote and chose to post; no roster field is read.

**Earlier versions** (`lib/private/notice-history.ts`, `NoticeHistory.tsx`). In the editor, under "Show to members" and "Ends on", a folded "Earlier versions (n)" list: one line per save (rows of one save share one time and one officer), newest first, with who, when and the fields changed; the newest says "Current version". Opened, a save shows each field's earlier text ("Before") beside what it saved ("Saved"), "First text" when there was none, or "Same text, marked up to date" for a "Keep as is". "Restore this version" (not on the current one) puts every field as it stood after that save into the editor: a changed language becomes a draft with Accept and Undo ("Draft from an earlier version, not saved"), the other fields take their earlier value, and a line says "Earlier version restored as a draft. Check it, then press Save." Nothing is saved until Save, which writes a new save; earlier rows are never changed. The editor reads the newest 300 edit rows; beyond that it says only the newest 300 are listed.

**Calendar link.** `calendar_entries.notice_id` (migration 0028; `on delete set null`). An entry links at most one notice; a notice can go with several entries.

- From the Calendar: the add and edit sheet has "Notice (optional)", a choice of the workspace's notices or "No notice". The agenda shows "Notice: <title>" under the entry, linked to the notice.
- From the notice: a "Calendar" section lists its entries with their next date in ST, each with "Remove link", and "Link a calendar entry" opens a sheet with the entries of this week and the next four (one line each, "Linked to another notice" when linking would move it).
- Both sides write the entry's `notice` field through the Calendar's own write, with its version (issue 293). The server checks that the notice belongs to the same workspace (400 otherwise).

**Images: not built.** No storage for pictures exists: D02 keeps Postgres for rows and rules out Blob for them, and neither `BLOB_READ_WRITE_TOKEN` nor any other storage variable is set. Vercel Blob would be a new dependency and service, which this session was told not to add. So a notice still has no image and the publish sends text only. Choosing a storage (Postgres `bytea` with a size cap, or Vercel Blob) is the owner's call.

**Not done here.** The read page keeps its stacked languages (no tabs). The Discord copy is not split: a language over 2,000 characters after escaping is too long to paste as one message.

**Amendment (2026-11-17, 11ah, D116).** Each copy button has a line under it, always shown, that says what it copies: "Cut to 1,000 characters, the game's limit.", "The whole text, never cut.", "Title in bold, formatted for Discord. Pings no one." (PT and FR to match). The labels are unchanged.

- Amendment (2026-11-18, 11ak, issue 419, D119): a notice with a picture posts it with the first message, as a webhook multipart attachment with an embed pointing at `attachment://notice.<ext>`; `allowed_mentions` stays empty.

**Amendment (2026-11-20, issue 451, D129): each workspace saves its own channels.** Officers paste each channel's webhook in Alliance settings → Discord; the server checks it with Discord (it must belong to the workspace's own server), stores it sealed under `WORKSPACE_KEYS_SECRET` (D124's seal) with the channel name and the forum flag, and never shows it again. Publishing, the garrison post and the weekly thanks use the saved webhook. `WORKSPACE_DISCORD_WEBHOOKS` stays, per channel, as the fallback until the workspace saves its own; "They are never stored in the database" no longer holds for a saved webhook, which is stored only encrypted. The line under an unset channel now reads "No Discord channel is set up for members’ notices yet. An officer can add it in Alliance settings." (and for leadership notices and the thanks sheet the same ending), in EN, PT-BR and FR; it was "Ask the site owner."

**Amendment 2026-11-22 (issue 585 batch 4, slice S1; personas under the owner's standing approval, `.specs/features/585-words/plan.md`): one way to write dates, times and zones.** The posted line reads "Posted to #guides-and-beyond by Rook · Tue, Nov 17, 14:02 ST · EN, PT" (PT "ter., 17 de nov. às 14:02 ST", FR "mar. 17 nov. à 14:02 ST"; it read "Tue, Nov 17 14:02 server time").
