## D68 — Charts are hand-built inline SVG server components, labels in HTML, no chart library (2026-11-16, owner, 08zzzx, issue #270)

Supersedes "no charts in v1" (the CLAUDE.md UI rule, DESIGN.md's never-list, D58's "charts (out of v1)") and answers #62's question of which chart technology. The owner asked for players to see their own daily progress (#270); a line over time is the plainest way to show it.

- **Evidence** (review of spike PR #183, 2026-11-16). Observable Plot cannot render on the server without linkedom or jsdom, which would be a new dependency. Plot's SVG renders blank or without labels in resvg, one of next/og's renderers. Hand-built SVG renders in next/og with both sharp and resvg. Satori refuses SVG `<text>`.
- **What a chart is.** An inline SVG drawn by a React server component (`app/_ui/charts/LineChart.tsx`), no chart library, no new dependency. The SVG holds shapes only: the line, a dot per reading, optional shaded bands (an event's Start to End) and the top and bottom hairlines. Shapes are drawn in a 100 × 100 box stretched to the chart's size (`preserveAspectRatio="none"`); strokes use `vector-effect="non-scaling-stroke"`, and each dot is a zero-length round-capped segment, so both keep their size when the box is stretched.
- **Labels are HTML, never SVG `<text>`.** The highest and lowest value sit beside the top and bottom lines, the first and last date under the chart, in flex boxes around the SVG. So the same component can draw inside the Discord picture (#276), which Satori renders.
- **Numbers beside every chart.** A chart only shows the shape; its numbers are in text or a table next to it (on the player page: the summary line and the readings table under Details). The SVG is `role="img"` with an `aria-label` that states the first and the last value with their dates (`ledger.chart`).
- **Colours from the tokens.** `currentColor` with token classes (`text-ink` for the line, `text-rule` for bands and hairlines), so dark mode follows and no colour literal enters `app/` (DESIGN.md "Enforcement"). Nothing is hover-only: no tooltips.
- **Interaction** (owner, 2026-11-16). A chart's state (a period, the compared events, a window) lives in the URL query and the server computes the figures, as `/events/compare?a=&b=` (D57) already does, so a link can be shared on Discord and the page works without JavaScript. A small client component may sit on top of a server-drawn SVG for tap-to-read values or for picking two readings; nothing is hover-only. Points closer than 44 px cannot each be a 44 px target (28 px measured in a prototype), so a period is always also pickable with From and To selects, and a tap on the chart is a shortcut. A chart library is considered only later, for a separate free-exploration page, and only on that page. The player page's chart (#270) has none of this yet.
- **Not done.** Axes with ticks, gridlines, legends inside the SVG, tooltips, zoom, several lines in one chart. Each would be added when a page needs it.
- **Amendment, 2026-11-16 (UX review).** The chart draws only the line, its dots and the two hairlines in the SVG; an event is an HTML band (at least 6 px wide, `bg-ink/50`, 3:1 or more against the paper in light and dark) behind the SVG, and the value labels are HTML at the height of the highest and lowest value. The value range is at least 5 % of the highest value, centred on the data and never below 0. What Satori needs to draw this component inside the Discord picture (#276), as measured on a prototype: explicit `display: "flex"` style props on every wrapper; explicit `width` and `height` on the `<svg>`; token colours as hex style values (`tokenColor()`), not classes or `currentColor`; a `viewBox` padded by about 6 px so the dots on the edges are not clipped. `vector-effect` is honoured. The Discord variant is not built yet.
- Amended 2026-11-16 (#319): bars may be HTML boxes (same rules: hand-built, server-rendered, labels and numbers in HTML, no library); a line chart stays SVG.
