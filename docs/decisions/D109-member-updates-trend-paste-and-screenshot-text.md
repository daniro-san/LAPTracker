## D109 — Member updates: the trend on the card, AD Tech 100 % complete, Paste updates, Read from a screenshot, and progress in the thanks (2026-11-17, owner, 11ab, issue 347; amends D80, D96)

Why: officers get new main squad and AD Tech values from members whenever someone sends them, and want to see what changed, record many members at once, and thank the members who progressed. The owner's correction (2026-11-16): there is no weekly round. No "not updated in 7 days" list, no progress counter, no "asked" marks. The owner added "Read from a screenshot" on 2026-11-17.

- **The trend on the card.** Main squad and AD Tech show the current value, the change since the version before, and the day the current value was saved: "10.2M (+400K since Tue, Nov 10)" with "Updated Tue, Nov 17" under it, and "74% (was 69%)". The facts are append-only (D80), so the version before is read from `member_facts` (`factHistory`, `lib/private/fact-trend.ts`). No version before, a cleared one, or the same value: no change is shown. "Updated …" is plain small text, never a warning, and is shown on pending and former members' cards too.
- **AD Tech at 100 % is complete.** `AD_COMPLETE` (100) moved to `fact-fields.ts`. The card shows "100% (complete)". The Members "Missing info" chip (`factsToAsk`) lists AD Tech only when it has no value, so a member at 100 % is never in it. A chat screenshot's or a Paste updates draft's AD Tech row for a member already at 100 % starts dropped, and the save does not write it ("AD Tech is already 100%: complete, not written again"), as 11k built it. The per-card editor is unchanged.
- **Registered members through chat screenshots.** Checked: a member update draft already proposes a new version for a member who has values (before → after on the row), saved as the next version "from a message"; a stale one gets D80's 409. Nothing was changed there.
- **Paste updates** (Members, under the legend). One member per line, any order: "Ana 10.2M 74%", "RC9-XY 8,442,626 · 42%", "Bo: AD 80". The name is every word before the first value or AD/squad word (`nameAndValues`); the rest goes through D80's parser. The lines are sent to `POST /api/w/[slug]/shots` as one page with the type Member update, so they become a member update draft. Its rows are matched like a chat screenshot's, and the officer lands on the draft's review: each row before → after, a member to confirm or pick, a new member offered for a name not found (D106), then Save. Text with a chat sender line ("Lv.27 [OGs] Ana") is still read as a chat. Lines with no name or no value are left out; when none is left, nothing is made and the sheet says so. As with the desk's Send screenshots (D100), the button stays busy until the draft exists; a draft has no request id. The per-card paste is unchanged.
- **Read from a screenshot.** A button beside the three paste boxes: Edit info's "Paste what they told you", Add a new member (the same editor), and Paste updates (several pictures). Each picture goes through the desk's reader, `POST /api/w/[slug]/shots/read` (PNG, status bar dropped, at most 1080 px wide, 4 MB, the reader's 20 s limit, one picture per request). The status bar constants moved to `lib/screenshot/status-bar.ts` so the browser can load them. Only the text lines come back. They go into the paste box: in the editor its reading runs at once ("Found 2 values. Check them, then Save."), in Paste updates the officer taps Check the updates. Nothing is saved without the officer. The picture is read in memory and never stored (D96). The route is officers only (it was already in `member-session.test.ts`) and answers 401 `signed_out`. It now reads one picture at a time per officer: a second request while one is being read gets 429 `busy`. The guard is per server instance. The input is `accept="image/*"` without `capture`, so an iPhone offers the photo library. "Reading…" while it reads; on a failure: "Couldn’t read this picture. Try a sharper screenshot, or paste the text."
- **Progress in the thanks.** The Members thanks box ("Top this week") gets a "Progress this week" list, and Home's members box a one-line version of it. A member is named when, in the game week of the newest daily update (server days):
  - AD Tech was saved at 100 % this week and the version before it was below 100 (a first value of 100 has nothing to compare with);
  - main squad might was saved this week at least **5 %** (`SQUAD_GROWTH`) above the newest value saved before the week began.
  - No value before the week: not named and not counted (D75). Members on a break are left out, as from the other thanks. New members are not left out: progress compares a member with their own earlier value, not with others.
  - The list is in name order, "AD Tech 100%" and "main squad +6%" beside the name. It is not a ranking.
- **D75.** No "didn't answer" list exists. "—" is no data and counts against no one.
