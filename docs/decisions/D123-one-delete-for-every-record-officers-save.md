## D123 — One delete for every record officers save: an audit of the desk's tables, one shared soft delete with a short Undo, and the first batch (Calendar entries, thefts, new members) (2026-11-19, owner, 11ao, issue 427 phase 1; amends D97, D106, D108, D118, D120)

Why: officers create test records and then cannot remove them (owner, 2026-11-18). Notices (D118) and roll calls (D120) were the first cases, each with its own copy of the same code. The owner asked for an audit of everything the desk saves, a lifecycle for each record type, and one pattern reused by every type.

### The rule

- **Owned record**: something an officer made on purpose and may have made by mistake. It can be deleted: a soft delete with who, when and the request id (D100), a short Undo, and a Home line. Where a type has a natural "done" state it can also be archived (roll calls, D120).
- **Append-only history**: a record of what happened, such as a version of a field, a mark, a post or a log row. It is never deleted. A mistake is corrected by a new row (a new version, a cleared value, a withdrawn record).
- **System**: written by the tick, the daily read or sign-in, not by an officer at the desk. Out of scope.

### The shared pattern

- **Repo:** `lib/repo/trash.ts`. A trashable table has `deleted_at`, `deleted_by` (`set null` when the account goes) and `delete_request_id`. A restorable one also has `restored_at`, `restored_by` and `restore_request_id` (notices only today).
  - `softDelete`: deletes a live row. A repeat under the same request id answers true without writing, also after that delete was undone, so a late replay never deletes again.
  - `undoDelete`: only the officer who deleted, only within `UNDO_MS` (60 s), only with the delete's request id. A table can add its own rule (a `guard`); a unique violation (23505) is a refusal, never a 500.
  - `restoreDeleted`: any officer, at any time, with its own request id (D118).
  - `isDeleted`: lets a save to a deleted record answer "deleted", not "not found".
  - `live(table)`: the condition on every other read of the table.
- **Client:** `app/(private)/_ui/DeleteRecord.tsx`.
  - `DeleteButton`: a text button in seal (44 px). It asks with `AskSheet`: "Keep it" is the main button and has the focus, Delete follows in seal. It sends once under the question's request id and answers after the question has closed, so a page replaced there never lands on the question's history entry.
  - `UndoLine`: "… deleted." with Undo for 10 s (`UNDO_SHOWN_MS`). The server allows Undo for 60 s. The line scrolls itself into view when it appears.
- **Notices and roll calls now use it, with no change in behaviour.** `lib/repo/notice-deletes.ts` is gone. `lib/repo/roll-call-deletes.ts` keeps only the roll call's own parts: its Undo rule ("no new roll call took its place", `placeFree`) and Archive. `NoticeDelete.tsx` and `RollCallManage.tsx` draw `DeleteButton` and `UndoLine`. Their words, URLs and history handling are unchanged. Their route tests pass unchanged.
- **Analytics (D115):** each type's route reports `delete` and `undo_delete` (the deleter's Undo). Notices keep `undo` and `restore` (D118).

### Batch 1: Calendar entries, thefts and new members

Chosen because the code had no way back for them. Calendar entries and thefts were deleted for good on one confirm. New members were "removed" with no record of who did it and no Undo.

**Migration `0046_record_delete`.**

- `deleted_at`, `deleted_by` and `delete_request_id` on `calendar_entries` and `thefts`.
- `deleted_by` and `delete_request_id` on `pending_members`. Its `dismissed_at` (D106) is the `deleted_at`: the schema names it `deletedAt`, and the column keeps its name.
- The one-theme-per-week index on `calendar_entries` now covers live rows only. A deleted Alliance Duel theme frees its week, and Undo is refused when a new theme took it.

**Calendar entries.**

- A delete that takes the whole entry is soft: a one-off's Delete, `all`, or a weekly entry ended from its first week. "Skip the week of …" and "End it from this week on" from a later week are unchanged. They change the entry, and the entry stays.
- `live` is on every read of `calendar_entries` in `lib/repo/calendar.ts`: the days' read (Calendar, Home, the members' board, roll calls, the garrison page), `findEntry` (an edit, a skip or a garrison save answers 404, "Someone deleted this event."), the week's theme, caravan seats, and a notice's linked entries.
- Its weeks, its roll calls and its garrison plan stay. A roll call of a deleted entry shows with the added ones, on its own day (as after D120's Calendar delete). Undo brings the entry back with all of them.
- **The live-entry rule (PR review, 2026-11-19).** The hard delete used to cascade (`entry_id` set null), and code read "`entry_id` is null" as "the entry is gone". A soft-deleted entry keeps its id on its rows, so these reads now ask for a live entry instead (`exists … calendar_entries … deleted_at is null`):
  - an Elixir Scramble team holds its members only while its entry is live (`otherTeams`, and the team picker's `teamCalls`), so a deleted entry's team frees them for the other team;
  - a roll call counts as added by hand when it has no live entry (`findAdded`), as after the old cascade;
  - the next siege's enemy might carries over only from a live entry's siege (`lastEnemyMight`).
  - Checked and already live through `lib/repo/calendar.ts`: the Calendar's days (roll call placement, the garrison page, the board), caravan seats, a notice's linked entries, and Home's garrison lines.
- Body: `{action: "delete", entry, scope, week, requestId, undo?}`. A whole-entry delete answers `{ok: true, deleted: true}`, and the Calendar then says "Event deleted." with Undo inside the card of the day the entry was on. The Calendar opens at today, so a line at the top of the page would be off screen (review, 2026-11-19). The Undo resends the same body with `undo: true`.
- The one-off's question: "Delete this event?", its title, day and time, "It leaves the Calendar, the Members’ board and Home. Its roll calls stay." (PT "Ele sai da Agenda, do Mural dos membros e do Início. As chamadas dele continuam.", FR "Il quitte l’agenda, le Tableau des membres et l’Accueil. Ses appels restent."). A weekly entry keeps its inline choices: skip a week, or end the repeat.

**Thefts.**

- "Delete" (was "Remove") on each entry opens "Delete this theft?" with the entry's time, member and type, and "It leaves the log, its counts and the Follow-up tab." The answers are "Keep it" and "Delete" (PT "Apagar este roubo?", "Manter", "Apagar"; FR "Supprimer ce vol ?", "Le garder", "Supprimer").
- The log then says "Theft deleted." with Undo, in the attacker's card, so the officer keeps their place; when the deleted theft was the attacker's last, the card goes and the line shows above the log (PR review, 2026-11-19).
- Undo is refused when a live theft of the same attacker, member and time was added meanwhile (`noTwin`): the same report imported or typed again would otherwise become a double.
- `live` is on `listThefts` and `hasAttacker`. The log, its week and all-time counts, the Follow-up tab's thefts and an attacker's follow-up leave a deleted theft out. A follow-up on an attacker whose only theft was deleted answers 404. The screenshot import's duplicate check sees live thefts only, so a deleted theft sent again is added again.
- Body: `{action: "remove", id, requestId, undo?}`.

**New members (D106).**

- "Remove" asks with the shared question and D106's words ("Remove {name} from the list? …", "Keep on list"). Remove is now drawn in seal.
- The list then says "Removed {name}." with Undo (PT "Tirado da lista: {name}.", FR "Retiré de la liste : {name}.").
- A matched pending member cannot be deleted or brought back by Undo (`unmatched` guard). "Bring back" (an add of the same name) still reopens a removed one at any time.
- Body: `{action: "delete", uid, requestId, undo?}`.

**Home (D108).**

- Three more parts in `lib/repo/desk-activity-trash.ts`: "Ana deleted “Test raid” from the Calendar", "Ana deleted a theft from the log" (never whose or by whom, D75), and "Ana removed Zephyrine from the new members" (PT "apagou “…” da Agenda", "apagou um roubo do registro", "tirou … dos membros novos"; FR "a supprimé « … » de l’agenda", "a supprimé un vol du registre", "a retiré … des nouveaux membres").
- Each line carries its record's id and is not in `GROUPED`, so deletes never group. Each part takes the page cursor (`< before`).
- A deleted entry's add, edit and garrison lines leave the feed, as a deleted roll call's marks do (D120). So do a deleted theft's add line and a removed new member's add line. An undone delete brings them back and has no line.

**Analytics:** `calendar`, `theft` and `new_member` each add `undo_delete`.
