## D76 — Which roster keys may be served: daily_tech, daily_honor and active unblocked; presence and coordinates blocked and neutralised in fixtures (2026-11-16, owner, issue #308)

Why: the repository is public, and about half of the JSON files under `fixtures/` held real players' map coordinates (`x`, `y`) and presence values (`online`, `last_online_at`, `joined_at`). The owner decided on 2026-11-16 which roster keys may be served and that the history is not rewritten. One rule now covers every key the roster blocked list names.

- **Unblocked: `daily_tech`, `daily_honor` and `active`.** They may be served as alliance-level aggregates on public pages. Per member they may be served only on `/admin` for the site's own alliance (`OWN_ALLIANCE_ID`), and in the private workspace under D71's rule below. A null `daily_tech` is unknown, never 0 (D71).
- **Still blocked: `x`, `y`, `online`, `last_online_at` and `joined_at`.** They stay in `raw_json` and are not returned by any query, route, page, log or message, public pages and `/admin` included. Measured on 2026-11-16: `online` was false for all 1,649 members and `last_online_at` and `joined_at` were empty in alliance rosters, so they carry no product value outside the workspace (D71).
- **D71 stands as written.** The private workspace rule (own alliance only, code under `lib/private`, copies and exports leave out `x`, `y`, `online` and `last_online_at`) is neither loosened nor tightened. `BLOCKED_ROSTER_KEYS` (`lib/queries/blocked-keys.ts`) is unchanged and its tests are unchanged; serving the three unblocked keys is a later change that edits that list on purpose.
- **Fixtures are neutralised, from now on only.** In every `fixtures/**/*.json` the values of `x`, `y`, `online`, `last_online_at` and `joined_at` are replaced by a neutral value of the same JSON type (numbers 0, booleans false, strings empty, null stays null); the keys stay, so the parsers and the blocked-key tests keep their shape. The function is `neutraliseFixture` in `scripts/neutralise-fixture.ts`; the record-fixture skill runs it on every body before the body reaches `fixtures/`. The scrub changed 33 of the 66 JSON files in HEAD.
- **No history rewrite** (owner, 2026-11-16). The earlier commits keep the real values.
- **`/admin/members`.** `?alliance=` with another tracked alliance lists no members (D70 listed any tracked alliance). Might unchanged recalls about 23 % of the members who stop playing (measured offline on 2026-11-16 over 20 alliances: 1,520 members present in 5 daily reads, compared with the live roster's weekly `active` being 0 or missing; precision 100 %, 88/88, recall 23 %, 88/382), so the page says that a member who is not listed may still have stopped.
- **Amendment 2026-11-17.** `/admin/members` is removed (D70 amendment); the per-member might lists are read in the alliance workspace only.
- **Amendment 2026-11-19 (D127, issue 458): what the unblocked keys mean.** `active` is daily quest points (live, resets at 00:00 ST), not weekly activity; `daily_honor` is Alliance Help coins today, max 1,000; `daily_tech` is tech donated today. The game sends null, never 0. The 2026-11-16 recall measurement above compared the live roster's `active` with 0 or missing, so it measured "no quest points yet that day", not a week without activity.
