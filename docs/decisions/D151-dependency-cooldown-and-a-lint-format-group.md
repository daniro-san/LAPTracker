## D151 — Dependencies wait 7 days before Dependabot proposes them, and formatter/linter bumps are their own group that never merges itself (2026-11-21, CI audit, issue 592; amends plan §11.6 and §12.4)

Why: Dependabot merged every new minor or patch release on its own within a week, and a merge to `dev` reaches the production build, which holds secrets, within hours. A compromised release is usually found and pulled within days, so a short wait removes most of that risk. Separately, PR #420 has been red since 2026-11-18. Prettier 3.10.1 measures Thai text narrower than 3.9.10 does, so it re-wraps 5 lines of `lib/i18n/th.ts` and re-pads the whole table in `lib/i18n/glossary/th.md`. Because prettier sat in the same group as `next` 16.4.6 and 9 other runtime updates, the formatter held them all back.

- **Cooldown.** `.github/dependabot.yml`: npm `cooldown` `default-days: 7`, `semver-major-days: 14`; github-actions `cooldown` `default-days: 7` (GitHub Actions supports only `default-days`). Cooldown applies to version updates only. Security updates still arrive at once, which is what they are for.
- **`lint-format` group.** prettier, eslint, `@eslint/*`, typescript-eslint and `eslint-plugin-*`, minor and patch. It is listed before `minor-and-patch` because a dependency goes into the first group it matches. `dependabot-automerge` skips it (`dependency-group == 'lint-format'`), so a person runs `pnpm exec prettier --write .` or `eslint --fix` in that PR when the new version formats or flags code differently. Runtime updates keep merging on their own.
- **No formatting change for #420.** The two Thai files cannot pass under both 3.9.10 and 3.10.1: each version rejects the other's output (checked with both on the files). The regrouping unblocks #420 instead. Dependabot reads `dependabot.yml` from the default branch (`main`), so it rebuilds #420 without prettier after the next release, and prettier then comes in its own `lint-format` PR.
- **Automerge hardening.** `dependabot-automerge` has `permissions: {}` at workflow level, with `contents: write` and `pull-requests: write` on the job only. The job runs only when both `github.actor` and the PR author are `dependabot[bot]`, and only on PRs into `dev`.
- **Not added: pnpm `minimumReleaseAge` and `trustPolicy`.** pnpm 12.16.1 supports both (`minimumReleaseAge` in minutes, strict when set explicitly; `trustPolicy: no-downgrade`). It checks every lockfile entry against them even on `pnpm install --frozen-lockfile`, and today's lockfile fails each one. `minimumReleaseAge: 10080` rejects `@posthog/core@1.68.0`, published 2026-11-15T14:18Z, so the setting can go in from 2026-11-22T14:18Z if nothing younger lands before then. `trustPolicy: no-downgrade` rejects `lefthook@2.2.2` as a "high-risk trust downgrade (possible package takeover)". That needs a look before the setting can go in. Until then, Dependabot's cooldown is the only enforced wait, and pnpm's built-in 1-day default (non-strict) still applies to new resolutions.
